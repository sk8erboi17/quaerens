This note explains what the test data in \texttt{order\_relations.tex} is used for. That file is input for the engine in \texttt{main.c}; it is read by the test \texttt{test\_maps\_and\_relations.c} in this folder.

\begin{enumerate}
\item \textbf{Purpose.} The file holds 14 statements about order relations, each to be proved. The statements are data: the engine knows none of them in advance.

\item \textbf{What is being tested.} Whether a given relation is an order, whether it is total, and whether it has a least or a greatest element, as for divisibility on $\mathbb{N}$; orders on products, on sets of subsets and on sets of maps.

\item \textbf{How the statements are written.} Every property is written out as a formula, not named: for instance ``$f$ is injective'' is $\forall a, b\ (f(a) = f(b) \implies a = b)$. The engine must work from these definitions.

\item \textbf{How to run it.} From the top folder of the repository:
\begin{verbatim}
cc -std=c11 -O2 -Wall -Wextra -o /tmp/test_maps_and_relations \
    tests/set_theory/test_maps_and_relations.c && /tmp/test_maps_and_relations
\end{verbatim}

\item \textbf{Expected result.} One \texttt{PASS} line for the file when every statement is proved with a written proof. Today the engine proves 1 of the 14 statements: the fourth, a relation between the parts of a set given by a rule of set algebra, unfolded into a statement of chapter 14 and decided by regions (paragraph 17r of \texttt{parser.c}). The first two, relations between numbers, are not proved: the search of chapter 18 stops. The others are reported as not supported, each with its reason: primes, complex numbers, the number of elements of a set, an order written between the elements ($x \le y$ with ${\le} \subseteq S \times S$), and relations on sets of maps or of parts. The test fails; the file states the goal.
\end{enumerate}
